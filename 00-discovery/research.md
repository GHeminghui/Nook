# iPad 教师资料管理方案 —— 调研报告

- 阶段：调研（discovery）
- 日期：2026-09-27
- 作者：项目组
- 关联：`decision.md`、`docs/adr/`

---

## 1. 摘要（TL;DR）

老师每天要为学生准备不同的教学资料，但在 iPad 上，**系统自带的「文件」App 和「图书」App 无法满足多维分类、打标签与高效检索**：

- 「文件」App 的标签功能**藏得深、能力弱**，且**标签与搜索相互割裂**；文件夹树是单一维度，无法同时按「科目 / 班级 / 知识点 / 日期」交叉归类。
- 「图书」App 本质是电子书阅读器，**不支持任意文件的分类、标签与层级管理**，PPT、图片、音视频放不进去。
- iPadOS 的沙盒机制决定：**没有像 macOS Finder 那样的全局文件系统**，很多"只在 Mac 上成立"的自动化方案在纯 iPad 环境下不可用。

结论：这是**真实且可解的痛点**。可行解法不是"换一个更好的文件 App"，而是**「云盘 + 统一命名规范 + 具备标签/全文检索能力的 App」组合**。详见第 7 节候选路线与 `decision.md`。

---

## 2. 背景与问题定义

### 2.1 背景

- 用户角色：教师，**每天**需要为学生准备不同的教学资料（课件、习题、讲义、图片、音视频等）。
- 使用设备：以 **iPad** 为主（是否具备 Mac / PC 待确认，见第 8 节约束）。
- 现状：资料主要放在 iPad 自带「文件」库或「图书」中。

### 2.2 问题定义

| 痛点 | 具体表现 |
|------|----------|
| **分类维度单一** | 文件夹树只能表达一层归属，无法同时表达"高一数学 / 3 班 / 函数 / 本周 / 习题"等多个维度 |
| **打标签困难** | 文件 App 标签入口深、需长按、无快捷键、标签选择器不可搜索；保存文件时无法即时加标签 |
| **检索弱** | 标签与搜索脱节；无按"标签组合"筛选；跨云盘统一搜索体验差；找不到历史资料 |
| **图书 App 不适用** | 只能放电子书/PDF，无标签、无目录结构、不支持 PPT/图片/音视频 |
| **分发环节缺位** | 备好资料后，"发给学生"（生成链接/导出文件）在 iPad 上没有顺畅路径 |

## 3. 目标用户与场景

**核心用户画像**：非技术型教师，日常备课节奏快，希望"少点击、找得到、发得出"。

**典型场景**：
1. 今晚备明天的课，需要从历史资料里找到"上次讲函数用的那份例题 PDF"。
2. 同一份讲义要发给 3 个班级，希望按班级区分不同版本。
3. 期末复习时，想一次性调出"本学期所有章节的习题"。

**关键诉求优先级**（初步）：
分组/分类 + 子文件夹层级 **与** 多维度标签（二者都必要，见 7.1）＞ 快速检索 ＞ 低学习成本 ＞ 便捷分发 ＞ 自动化 > AI 辅助；另需**支持 HTML 单文件预览与收录**（见 7.1 P0-8）。

## 4. 现状分析：iPad 原生能力与局限

### 4.1 「文件」App

**已具备**：
- 支持为文件/文件夹打标签（iPadOS 26 起可自定义标签颜色，支持自定义文件夹颜色与图标、分栏视图、把常用文件夹拖入程序坞）[^1][^2]。
- 集成 iCloud Drive 与第三方云服务（Dropbox/OneDrive 等）[^8]。

**局限**：
- 标签**只能通过触摸长按添加**，无键盘快捷键；标签列表**不可搜索**，标签一多就难选[^3]。
- **标签与搜索割裂**：无法用"标签 + 文件类型 + 日期"组合做高级检索（macOS Finder 可以）[^3]。
- 保存文件（"存储到文件"）时**无法同时打标签**，需保存后再回文件 App 补打[^3]。
- 视图与排序选项少（长期只有列表/网格）[^3]。

### 4.2 「图书」App

- 定位是电子书阅读器，**不支持任意格式文件的分类/标签/层级管理**，属于"错误的工具"。

### 4.3 「备忘录」App（值得注意的对照）

「备忘录」原生支持 **`#标签` + 智能文件夹（Smart Folder）**，可按标签、创建时间、编辑时间组合筛选，且标签可重命名/删除[^4]。
→ 启示：**Apple 自家的"标签+智能文件夹"范式是被验证可行的**，只是「文件」App 没有把它做好。这提示我们优先寻找"具备标签 + 智能分组"能力的第三方方案。

### 4.4 检索能力（Spotlight / Siri）

- Spotlight 可索引部分文件；Apple Intelligence 的语义检索能"找到命名很烂的文件"，**但不会自动整理**——它只帮"看"，不帮"归"[^7]。
- 检索能力受限于**文件是否被索引**、**命名是否规范**。

### 4.5 自动化：「快捷指令」与 Apple Intelligence

- 「快捷指令」可做：批量重命名、移动、按条件归档等[^5][^6]。
- 结合 Apple Intelligence 可**按内容自动生成更可读的文件名**（图片/PDF）[^6]。
- 局限：iPad 上**没有 Mac 的 Finder 快捷操作 / 文件夹动作**，纯拖拽式自动归档能力弱；复杂自动化需 Scriptable 等，门槛较高。

## 5. 竞品与方案调研

将候选方案分为四类。

### A 类：原生轻量方案（零成本）

「文件」App + iCloud Drive + 严格命名规范 + 标签 + 「快捷指令」自动重命名。

- 优点：零成本、无学习成本、无第三方依赖。
- 缺点：标签/检索能力弱（见 4.1），只能靠"命名规范"硬抗检索。

### B 类：增强型文件管理 / 云盘方案

| 方案 | 关键能力 | 备注 |
|------|----------|------|
| **Documents (Readdle)** | 文件标签、压缩、跨云盘（iCloud/Dropbox/Google Drive）双向同步[^8] | 免费为主，上手快 |
| **TagSpaces** | 标签写入**文件名或 sidecar**，文件自带标签、跨平台、纯本地/离线、无账号[^9] | 标签"跟着文件走"，不锁定 |
| **坚果云** | 文件标签、实时同步、**无限历史版本**、共享与权限[^10] | 国内网络友好，教师团队常用 |
| **飞书 / 语雀 / 阿里云盘** | 云端文档、知识库、分享链接 | 在线文档强，本地文件管理弱 |

- 优点：比原生强，成本低，国内可用性好。
- 缺点：标签+高级检索仍不如专用文档管理软件；跨 App 检索体验参差。

### C 类：知识库 / 文档管理类（检索与标签最强）

| 方案 | 关键能力 | 代价 |
|------|----------|------|
| **DEVONthink To Go**（iPad/iPhone） | 数据库/分组/**自定义智能分组**、标签、自定义元数据、**强搜索**、OCR、交叉链接（做 wiki）、集成「文件」App、支持快捷指令、可接本地/在线 AI[^11][^12] | 付费、概念多、**学习曲线陡** |
| **Obsidian** | 本地 Markdown、`#标签`（支持多级）、全文搜索极快、双向链接、插件生态；教师可搭建学科知识库[^13][^14] | 仅管 Markdown 笔记与附件，**不适合当通用文件管理器**；iOS 端为付费 |
| **Notion** | 数据库（标签/多视图：表/看板/日历）、云同步、免费个人版[^15] | 云优先、大附件弱、离线弱 |

- 优点：**标签 + 组合筛选 + 全文检索**能力最强，正好命中核心痛点。
- 缺点：学习成本高，对"通用文件（PPT/音视频）"的适配程度不一。

### D 类：自建 / NAS 方案

群晖 Synology Drive、Nextcloud、WebDAV + 文件 App 挂载。

- 优点：数据自主、容量大、隐私强。
- 缺点：需要额外硬件与运维，**教师个人场景性价比低**。

### 5.1 关键结论

1. **没有单一 App 能"一键解决"**——最优解是「存储层（云盘）+ 规范层（命名/结构）+ 检索层（标签 & 全文搜索）」的组合。
2. **"文件夹层级 + 标签 + 智能分组"三者需同时具备**：「备忘录」证明了"标签 + 智能文件夹"可行，但用户明确要求**保留分组/分类与子文件夹层级**——因此只支持标签、没有文件夹树的方案（部分纯 PKM 工具）应排除。
3. **纯 iPad 场景要避开"仅 Mac 可用"的方案**（Finder 动作、Hazel 等）。

## 6. 技术可行性分析

| 维度 | 结论 |
|------|------|
| **文件系统访问** | iPadOS 沙盒限制，无全局文件系统；跨 App 文件访问依赖 Files 的 Document Provider。选型须确认 App 是否集成「文件」App[^11] |
| **存储与同步** | iCloud Drive / 坚果云 / 飞书 均可多端同步；需评估容量与国内访问稳定性[^10] |
| **标签能力** | 原生弱（4.1）；第三方可实现（B/C 类）[^9][^11] |
| **全文检索** | 依赖 OCR 与索引；C 类工具（DEVONthink/Obsidian）表现最好[^11][^14] |
| **自动化** | 「快捷指令」可覆盖重命名/归档；Apple Intelligence 可辅助命名，但**不自动整理**[^6][^7] |
| **分发** | 云盘分享链接最顺；iCloud 链接、坚果云分享、飞书均可[^10] |
| **本地 HTML 预览** | 原生「文件」快速查看**不支持 HTML**（官方仅列图像/PDF）[^17][^18]；需专用本地查看器（如 Html Preview，免费、纯本地、无内购）或自带 WebView 的文件管理器；**单文件内联 CSS/JS 可正常渲染，外链资源与多页跳转会失效**[^19] |

**总体判断：技术可行。** 不存在硬性技术阻断，主要变量是"工具复杂度 vs 用户学习成本"的取舍。

## 7. 需求清单与候选路线

### 7.1 需求清单

**P0（必须）**
1. **分组/分类管理 + 子文件夹层级**（用户明确要求为必要项）：用稳定的文件夹树承载"科目 / 班级"等**主归类**，支持多级子文件夹、可逐层浏览与批量移动。
2. **多维度标签**：在文件夹之外，用标签表达"知识点 / 日期 / 类型 / 状态"等**交叉维度**，且能与第 1 项的文件夹范围**叠加筛选**。
3. **快速检索**：文件名 + 全文 + 标签组合；检索须同时覆盖文件夹层级与标签。
4. **统一命名规范**与**目录层数受控（建议 ≤5 层）**，保证可索引、可检索[^16]。
5. **多端同步**（iPad / iPhone / 电脑 一致）。
6. **低学习成本**：日常高频操作 ≤ 2 步完成。
7. **一键分发与打印**：能一键分享到**微信/QQ**（国内主渠道），也支持**导出/打印**成纸质。
8. **HTML 单文件预览与收录**（用户新增需求）：能把 **AI 生成的单文件 `.html`** 收录进资料库，并在 iPad 上**直接渲染成可读页面**（而非显示源码或图标）。

> 说明：第 8 条是新增需求。iPad「文件」App 的**快速查看官方仅支持图像与 PDF，HTML 不在其列**，本地 `.html` 常显示为图标或源码[^17][^18]，因此选型时必须确认"能否渲染本地 HTML"。

**P1（重要）**
7. 拍照扫描成可搜索 PDF（OCR）。
8. 轻量自动化：按命名自动归档 / 自动打标签（快捷指令）。
9. 版本历史 / 防误删。

**P2（加分）**
10. 手写批注、AI 辅助命名与摘要。
11. 与课件制作工具联动。

### 7.2 候选路线（供设计阶段择一或组合）

| 路线 | 构成 | 适合谁 | 主要风险 |
|------|------|--------|----------|
| **路线 1 轻量** | iCloud/坚果云 + 文件 App 标签 + 备忘录智能文件夹 + 快捷指令 | 不想花钱、能接受弱检索 | 检索痛点缓解有限 |
| **路线 2 均衡（倾向推荐）** | 云盘 + **统一命名规范** + 一款带标签与全文检索的工具（Documents / TagSpaces / 坚果云 组合） | 大多数教师 | 仍依赖"命名纪律" |
| **路线 3 知识库** | 云盘存文件 + DEVONthink To Go 或 Obsidian 做**索引/标签/检索层** | 愿投入学习、资料量大 | 学习曲线陡、部分付费 |

> **选型前提（据用户补充）**：方案**必须同时支持"文件夹层级（含子文件夹）"与"标签"两种组织方式**——纯标签、没有文件夹树的方案不满足要求；反之只靠文件夹、没有标签的方案也无法解决多维交叉归类；此外**须能渲染本地单文件 HTML**（AI 生成资料，见 P0-8）。

> 最终路线选择在**设计阶段**（`01-design/`）确定；约束条件已确认，见第 8 节。

## 8. 已确认信息与约束

### 8.1 用户确认（2026-09-27）

| # | 问题 | 用户答复 | 对选型的影响 |
|---|------|----------|--------------|
| 1 | 资料类型 | **以 PDF/课件 + 图片为主**；**另需支持 AI 生成的单文件 HTML 预览与收录** | 需支持 PDF/图片浏览与批注，且**必须能渲染本地 `.html`** |
| 2 | 设备栈 | **当前以 iPad 为主**；Mac 作为**后续版本**（本阶段不考虑） | 设计仅面向 iPad，**避开"仅 Mac 可用"方案**；保留未来接 Mac 的余地 |
| 3 | 分发方式 | **需要**：微信/QQ 发文件；**也需要**打印成纸质 | 资料库须支持一键分享到微信/QQ 与打印/导出 |
| 4 | 预算 | **先免费**，后续再考虑订阅或买断 | 方案先基于免费能力落地，并预留升级路径 |
| 5 | 隐私 | **本地为主，iCloud 可做云端备份**（先行规划） | 首选本地存储；iCloud 作为备份/同步层，不依赖公有云 |

### 8.2 派生的硬性约束

- 只在 **iPad（iPadOS）** 上交付，不引入"仅 Mac 可用"的自动化。
- 资料库须**同时支持文件夹层级（含子文件夹）与标签**（见 7.1 P0-1/2）。
- 须能**渲染本地单文件 HTML**（见 7.1 P0-8 与第 6 节）。
- 须能**分享到微信/QQ 并支持打印**（见 7.1 P0-7）。
- **零成本起步**：优先"原生 + 免费工具"组合，并预留后续付费升级接口。
- **本地优先**：数据默认存于 iPad 本地，iCloud 仅作备份/同步。
- 目标用户为非技术型教师，**方案必须易用**；国内网络环境，优先国内可稳定访问的服务。

> Mac 端能力、订阅/买断升级方案列为**后续版本**，本阶段不纳入设计范围。
