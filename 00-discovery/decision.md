# 调研阶段 Go / No-Go 决策记录

- 阶段：调研（discovery）
- 日期：2026-09-27
- 决策者：项目组（待用户确认）
- 关联：`research.md`

---

## 背景

教师在 iPad 上每日备课、分发资料，「文件」App 与「图书」App 在多维分类、打标签与检索上均不满足需求（详见 `research.md` 第 2、4 节）。需判断：**是否值得立项进入设计阶段，投入去构建一套"iPad 资料管理方案"**。

## 决策

**结论：Go（继续进入设计阶段）。**

理由：
1. **需求真实且高频**：每日备课、按班级/科目/知识点复用资料，是持续性痛点，非偶发。
2. **技术可行，无硬性阻断**：云盘 + 标签/全文检索类工具的组合方案在纯 iPad 环境下可落地（`research.md` 第 6 节）。
3. **已有可复用范式**：Apple「备忘录」的"标签 + 智能文件夹"证明该思路可行，市场亦有成熟工具（DEVONthink To Go、TagSpaces、坚果云等）。
4. **收益明确**：目标是把"找资料"从数分钟降到数秒，并顺畅完成分发。

> 说明：本决策仅代表"值得继续设计"，**不等于已选定具体工具**；工具选型在设计阶段确定。

## 备选方案

| 方案 | 说明 | 选择结果 |
|------|------|----------|
| A. 直接沿用现状 | 继续用「文件」+「图书」 | 否决：痛点未解，且为用户明确提出的诉求 |
| B. 仅换一个更强文件 App | 只换 App，不改命名/结构 | 否决：单点替换无法解决多维度分类与检索 |
| C. 立项设计组合方案 | 云盘 + 命名规范 + 标签/检索工具，产出可执行方案 | **采纳（Go）** |
| D. 自建 NAS | 数据自主但需硬件与运维 | 暂不考虑：个人教师场景性价比低 |

## 后果

- **正面影响**：获得一套面向教师、纯 iPad 可用的资料管理方案，显著降低备课检索成本。
- **负面影响 / 风险**：
  1. 方案效果**依赖"命名纪律"**，用户执行力不足会退化。
  2. 部分强检索工具（DEVONthink To Go 等）学习曲线陡、可能付费，与"低学习成本"存在张力。
  3. **"本地优先 + 免费起步"与"强检索能力"存在折中**：免费工具检索偏弱，强检索工具多需付费，需在设计阶段平衡；Mac 端延后到后续版本，跨端体验暂不完整。
- **后续动作**：
  1. 5 项选型约束**已确认**（见 `research.md` 第 8.1 节），设计阶段直接沿用：以 PDF/图片为主且**需 HTML 单文件预览**、仅 iPad、需微信/QQ 分享与打印、先免费后付费、本地为主 + iCloud 备份。
  2. 设计阶段输出 `product-spec.md`（选定的路线与操作流程）与 `tech-design.md`（工具组合、命名规范、目录结构）；**选型须同时支持"分组分类 + 子文件夹层级"与"标签"，并能渲染本地单文件 HTML**（用户已明确要求）。
  3. 若选型涉及付费/隐私取舍，按 `docs/adr/000-template.md` 补一条 ADR。
